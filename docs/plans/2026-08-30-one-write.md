# One Write Implementation Plan

**Goal:** One Freighter prompt creates a funded allowance; one Freighter prompt saves any set of edits.
**Architecture:** `deposit` and `set_rules` collapse into `write(agent, rules, usdc_in, xlm_to_agent)`, which moves USDC in and XLM to the agent in a single Soroban invocation. `withdraw` loses its destination. The constructor loses `agent`/`rules` and gains `native`, so a cancelled create leaves a reusable blank rather than a contract with a dead agent welded to it.
**Tech Stack:** Rust + soroban-sdk 25, Next.js 16.3.1, React 19, `@stellar/stellar-sdk` 16.2.0, Supabase, Node 22.14, `node:test`.

**Spec:** [`docs/specs/2026-08-30-one-write-design.md`](../specs/2026-08-30-one-write-design.md)

```rust
    /// Runs once, at deployment, as part of the same transaction.
    ///
    /// A separate `init` would have needed the owner's signature to prove they wanted to be
    /// the owner — which means the owner needs XLM for fees before they can own anything, and
    /// that is the barrier this product exists to remove. It would also leave a window between
    /// deploy and init in which anyone could claim ownership of the empty contract.
    ///
    /// A constructor closes both: the platform pays, the owner is set atomically, and there is
    /// no moment where the contract exists unowned.
    ///
    /// The agent and the rules are deliberately *not* set here. They arrive with the owner's
    /// first `write`, so a create abandoned at the signature leaves a contract that is still
    /// theirs and still finishable, rather than one naming an agent whose key was never saved.
    ///
    /// `native` is the native XLM asset contract. `write` moves XLM through it to fund the
    /// agent's account; Soroban cannot derive the address, and taking it per-call would make it
    /// a value a caller could get wrong.
    pub fn __constructor(env: Env, owner: Address, token: Address, native: Address) {
        env.storage().instance().set(&DataKey::Owner, &owner);
        env.storage().instance().set(&DataKey::Token, &token);
        env.storage().instance().set(&DataKey::Native, &native);
        env.storage().instance().set(&DataKey::Revoked, &false);
    }
```

```rust
    /// Everything the owner writes, in one invocation and therefore one signature.
    ///
    /// The owner is loaded rather than passed. `deposit` used to take a `from` only to check it
    /// against the owner the contract already knew, which is an argument that can be wrong for
    /// no benefit. Owner auth covers both nested transfers through the auth tree.
    ///
    /// Order matters: rules are applied before money moves, so a rejected rule change cannot
    /// leave funds sitting against rules that were never applied.
    pub fn write(
        env: Env,
        agent: Option<Address>,
        rules: Option<Rules>,
        usdc_in: i128,
        xlm_to_agent: i128,
    ) -> Result<(), AllowanceError> {
        if usdc_in < 0 || xlm_to_agent < 0 {
            return Err(AllowanceError::InvalidAmount);
        }
        let owner = require_owner(&env)?;

        if let Some(agent) = agent {
            if env.storage().instance().has(&DataKey::Agent) {
                return Err(AllowanceError::AgentAlreadySet);
            }
            env.storage().instance().set(&DataKey::Agent, &agent);
        }

        if let Some(rules) = rules {
            env.storage().instance().set(&DataKey::Rules, &rules);
        }

        if usdc_in > 0 {
            let token_address = token_address(&env)?;
            token::TokenClient::new(&env, &token_address).transfer(
                &owner,
                &env.current_contract_address(),
                &usdc_in,
            );
            Deposited { from: owner.clone(), amount: usdc_in }.publish(&env);
        }

        if xlm_to_agent > 0 {
            // Straight from owner to agent. The contract never holds XLM, so there is no
            // balance here for anyone to argue about.
            let agent: Address = env
                .storage()
                .instance()
                .get(&DataKey::Agent)
                .ok_or(AllowanceError::NotInitialized)?;
            let native: Address = env
                .storage()
                .instance()
                .get(&DataKey::Native)
                .ok_or(AllowanceError::NotInitialized)?;
            token::TokenClient::new(&env, &native).transfer(&owner, &agent, &xlm_to_agent);
        }

        Ok(())
    }
```

```rust
    /// Owner reclaims funds. No rules apply — the rules constrain the agent, not the owner.
    ///
    /// The destination is the stored owner and is not a parameter. Freighter renders a Soroban
    /// invocation as a contract call rather than a legible payment, so a signature over a
    /// caller-supplied destination would not be meaningful review of it. Fixed, the worst this
    /// path can do is return the owner their own money.
    ///
    /// The outbound transfer needs no signature: the contract is the executing contract, so
    /// its own `require_auth` is satisfied by Contract Invoker authorization.
    pub fn withdraw(env: Env, amount: i128) -> Result<(), AllowanceError> {
        if amount <= 0 {
            return Err(AllowanceError::InvalidAmount);
        }
        let owner = require_owner(&env)?;

        let token_address = token_address(&env)?;
        token::TokenClient::new(&env, &token_address).transfer(
            &env.current_contract_address(),
            &owner,
            &amount,
        );

        Withdrawn { to: owner, amount }.publish(&env);
        Ok(())
    }
```

```ts
/**
 * Everything the owner changes, in one signature.
 *
 * Undefined means "leave it alone" and becomes a Soroban `None`, so a save that only added
 * credits cannot clear the allowlist. Amounts are additive: `usdcIn` adds to the balance, it
 * does not set it.
 */
export async function write(
  address: string,
  allowanceId: string,
  changes: {
    agent?: string;
    rules?: { maxPerCall: bigint; windowLedgers: number; windowCap: bigint; allowlist: string[] };
    usdcIn?: bigint;
    xlmToAgent?: bigint;
  },
): Promise<string> {
  const server = new rpc.Server(RPC_URL);
  const account = await server.getAccount(address);

  const built = new TransactionBuilder(account, { fee: '5000000', networkPassphrase: PASSPHRASE })
    .addOperation(
      new Contract(allowanceId).call(
        'write',
        option(changes.agent, (a) => arg.address(a)),
        option(changes.rules, (r) => rulesScVal(r)),
        arg.i128(changes.usdcIn ?? 0n),
        arg.i128(changes.xlmToAgent ?? 0n),
      ),
    )
    .setTimeout(120)
    .build();

  return signAndSubmit(address, built, 'Saving');
}

/** Soroban `Option<T>`: a present value, or void. */
function option<T>(value: T | undefined, toScVal: (v: T) => xdr.ScVal): xdr.ScVal {
  return value === undefined ? xdr.ScVal.scvVoid() : toScVal(value);
}
```

```ts
/**
 * What actually changed, as `write` arguments.
 *
 * Undefined means "leave it alone". A save that only added credits must not carry a rules
 * object, or it would rewrite the allowlist with whatever the form happened to hold.
 */
function diff(allowance: AllowanceRow, form: FormState) {
  const rulesChanged =
    form.allowlist.join() !== (allowance.rules?.allowlist ?? []).join() ||
    form.windowCap !== currentWindowCap(allowance) ||
    form.windowMinutes !== currentWindowMinutes(allowance);

  return {
    agent: allowance.agent_address === null ? form.agent : undefined,
    rules: rulesChanged ? toRules(form) : undefined,
    usdcIn: form.addUsdc ? stroops(form.addUsdc) : 0n,
    xlmToAgent: form.topUpXlm ? stroops(form.topUpXlm) : 0n,
  };
}

/** True when there is nothing on-chain to send. Save may still rename. */
function empty(changes: ReturnType<typeof diff>) {
  return (
    changes.agent === undefined &&
    changes.rules === undefined &&
    changes.usdcIn === 0n &&
    changes.xlmToAgent === 0n
  );
}
```

## Self-review

**Spec coverage.** Every section of the spec maps to a task: contract surface → 1–4, deployment
and blanks → 8, schema → 6, API → 8–9, UI → 10–12, callers → 13, rollout → 5 and 14. The one
spec item deliberately deferred is publishing the client SDK, which the spec also lists as out of
scope.

**Placeholders.** Two literals are intentionally not written here — `ALLOWANCE_WASM_HASH` (Task 5)
and the USDC SAC in the backfill (Task 6). Both are environment values that must travel file → CLI
→ Vercel and never through a conversation.

**Type consistency.** `write` takes `(agent, rules, usdc_in, xlm_to_agent)` in that order in the
contract, the wrapper, and the diff. `funded` is the API field; `unfinished`/`unfunded` are the UI
states derived from it, and they are different things on purpose.

**Known risk.** Task 3 assumes `token::TokenClient::transfer` on the native SAC creates a missing
account. That is established on testnet by spike, but `env.register_stellar_asset_contract_v2`
in Rust tests may not model account creation the same way. If `one_write_moves_usdc_in_and_xlm_to_the_agent`
passes in Rust, that is not proof for the real network — Task 14's click-through is.
